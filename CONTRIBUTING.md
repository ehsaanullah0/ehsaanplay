
# Contributing to EHSAAN PLAY

Thank you for your interest in EHSAAN PLAY!

EHSAAN PLAY is an independently developed project maintained and controlled by **[@ehsaanullah0](https://github.com/ehsaanullah0)**. The project follows a maintainer-controlled development approach to ensure consistency, stability, security, and a clear development direction.

Please read this document carefully before proposing any changes.

## 1. Contribution Policy

**EHSAAN PLAY does not accept unsolicited Pull Requests (PRs).**

The project maintainer, `ehsaanullah0`, reserves full authority over the project's source code, design, features, functionality, and development decisions.

The following rules apply:

- Pull Requests containing new features are not accepted.
- Pull Requests involving modifications, alterations, or redesigns are not accepted.
- Unsolicited code changes, optimizations, or refactoring proposals are not accepted.
- No contributor is authorized to modify the project without prior verification and explicit permission from `ehsaanullah0`.
- Opening a Pull Request does not grant permission to contribute or modify the project.

These restrictions apply regardless of the size or nature of the proposed change.

## 2. Bug Reporting

If you discover a bug, unexpected behaviour, compatibility issue, or security concern, the **only accepted way to report it is by opening a GitHub Issue**.

Before submitting an issue:

1. Check existing issues to avoid duplicate reports.
2. Clearly describe the problem.
3. Provide steps to reproduce the issue.
4. Include relevant screenshots, logs, or other supporting information when possible.
5. Mention your device, operating system, and application version when relevant.

Please use the appropriate issue category or template if available.

**Important:** Reporting a bug does not automatically authorize you to fix it or modify the project's source code.

The maintainer will review the report and decide whether and how the issue should be addressed.

## 3. Permission-Based Changes

Users may recommend improvements, suggest changes, or offer potential solutions. However, any implementation or modification requires prior verification and explicit permission from `ehsaanullah0`.

The process is as follows:

1. Open a GitHub Issue describing the proposed change or solution.
2. Wait for the maintainer to review your proposal.
3. Obtain explicit permission from `ehsaanullah0` before making any modifications.
4. Follow the instructions and scope approved by the maintainer.
5. Only proceed with an authorized contribution through the method specified by the maintainer.

Without explicit permission, contributors must not submit modified source code, create feature branches for proposed changes, or open Pull Requests.

## 4. Features and Enhancement Requests

Feature additions, UI alterations, redesigns, functionality changes, and other enhancements are controlled exclusively by the project maintainer.

You may share your ideas or recommendations through GitHub Issues, but:

- Suggestions are not guarantees of implementation.
- The maintainer has the final decision on whether a suggestion is considered.
- No feature or alteration should be independently implemented.
- No Pull Requests for feature additions or alterations will be accepted.

The project's roadmap and development priorities remain under the control of `ehsaanullah0`.

## 5. Code Ownership and Authorization

All project development decisions and source code modifications are subject to the maintainer's approval.

By interacting with this repository, users acknowledge that:

- They do not have automatic permission to modify the project.
- They cannot independently introduce features or alter existing functionality.
- They must obtain explicit authorization before making approved changes.
- The maintainer reserves the right to reject unauthorized contributions without further explanation.

## 6. Pull Request Policy

**Pull Requests are not an accepted contribution channel for unsolicited changes.**

Any Pull Request submitted without prior authorization may be closed without review.

This includes, but is not limited to:

- New features or functionality.
- UI/UX changes and redesigns.
- Code refactoring or restructuring.
- Performance optimizations.
- Configuration or dependency alterations.
- Bug fixes submitted without prior authorization.

If you believe you can help resolve an issue, report it through GitHub Issues first and wait for the maintainer's response.

## 7. Final Authority

`ehsaanullah0` retains exclusive authority over:

- Project direction and roadmap.
- Feature selection and implementation.
- Source code modifications.
- Design and interface decisions.
- Security and architectural decisions.
- Approval or rejection of proposed contributions.

The maintainer's decision regarding contributions and project modifications is final.
